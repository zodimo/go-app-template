## Why

This repository is intended to be a **public Go project starter template** that a stranger can clone or copy and have a working, renamed application in one step. Today it is stranded between a reusable architecture and a hardcoded `go-cli`/`github.com/zodimo` identity, so forking means manual, error-prone find-and-replace across ~35 files (module path, app name, `GOCLI` env prefix, cobra `Use:` strings, `cmd/` directory names, panic tags, gitignore entries, filenames). It also ships machine-local runtime artifacts (`go-cli-config.json`, `.go-cli/`) that break for any fork and are incompatible with a public template. The README promises a Makefile and a `--cwd` flag that do not exist, and the project has no commit history.

The goal: turn this into a self-scaffolding template where the modular plumbing (config, logging, database, migrations) is preserved as-is, but identity is **driven from a single runtime source**, a `setup` command performs deterministic, idempotent re-identity after cloning, and no generated or machine-local state is ever shipped.

## What Changes

- **New `setup` cobra command** embedded in the app (e.g. `myapp setup`) that interactively collects app identity and rewrites the project (Layer 2 re-identity). Stdlib-only prompts, no new third-party dependencies. Idempotent and re-runnable so renaming later is non-destructive.
- **Single source of truth for identity** via a wizard-generated `internal/identity/identity.go` (`AppName`, `ConfigName`, `EnvPrefix`, `DataDir`, `BinTrio`).
- **Module path handling** via `golang.org/x/tools/cmd/gonew` (AST-aware module + import rewrite) documented as the Layer 1 clone flow; **BREAKING** none — module path is unchanged until a consumer clones.
- **Remove hardcoded `go-cli` literals** from `internal/config/config.go` (appName, configName, envPrefix, defaultDataDirectory), cobra `Use:` strings, panic-recovery tags, and default log/db filenames, replacing them with reads from the identity source.
- **Wizard renames the binary trio** (`cmd/cli`, `cmd/cli-config`, `cmd/cli-migration`) and their cobra `Use:` / panic tags to the target app's names.
- **Template hygiene (Layer 3)**: never commit `go-cli-config.json`, `.go-cli/`, or test panic logs; config is generated by `config init` on first run; delete existing committed artifacts.
- **Documentation**: fill in README sections (config resolution, logger, database, version, makefile), add a real or documented Makefile, add a contributor/scaffold guide.
- Fix bug debt surfaced during exploration: missing `--cwd` flag (README claims it exists), `RecoverPanic("cli-config-main")` copy-paste error in `cmd/cli-migration/main.go`, stray `fmt.Println(err)` in `internal/commands/root.go`, dead `commands.Execute()` path that bypasses `--json`.

## Capabilities

### New Capabilities
- `app-identity`: Single-source runtime-driven application identity that replaces scattered hardcoded `go-cli`/`GOCLI` literals (app name, config name, env prefix, data directory, binary trio). Provides read APIs used by config, logging, and database defaults, with an overridable file the wizard generates.
- `project-scaffolding`: The `setup` cobra command and the documented gonew-based clone flow that together let a consumer produce a working, renamed application deterministically. Covers interactive identity collection, stdlib prompting, rewriting files (identity file, cmd dirs, cobra Use, panic tags, gitignore), and the idempotent/re-runnable guarantee.
- `template-hygiene`: The contract that no machine-local or generated runtime artifacts are committed, config is generated on first run, stale test artifacts are absent, and filesystem locations are derived from the single identity source rather than hardcoded absolute paths.

## Impact

- **Code**: `internal/config/config.go`, `internal/config/viper.go`, `internal/config/commands/init.go`, `internal/commands/root.go`, `internal/config/commands/root.go`, `internal/database/commands/root.go`, `cmd/cli`, `cmd/cli-config`, `cmd/cli-migration` `main.go` files, `.gitignore`, `README.md`.
- **New files**: `internal/identity/identity.go` (wizard-generated), `internal/commands/setup.go` (or `internal/scaffold/`), possibly `Makefile`.
- **Removed/ignored**: committed `go-cli-config.json`, `.go-cli/`, `internal/logging/logging.test-panic-*.log`.
- **Dependencies**: `github.com/zodimo/go-maybe` remains an external, documented dependency (not vendored). `golang.org/x/tools/cmd/gonew` is documented for consumers but not added as a module dependency.
- **Build**: The template itself must eventually be published as a versioned Go module for the gonew `@version` clone path to work (tag + `go list -m -versions`).
- **Tests**: Existing config/logging tests that assert `GOCLI_DATABASE_DATABASE` env values must be updated to read from the identity source.
